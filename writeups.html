Lab Write-Ups

Kunci jawaban langkah-demi-langkah untuk lab offensive dan blue team di sandbox. Selalu coba sendiri dulu sebelum membaca solusi — yang benar-benar diserap adalah jalan yang kamu temukan sendiri.

01 — write-up offensive

Lab Serangan: nmap → SSH → Root → Pivot

Misi: masuk ke lab-web-01 (192.168.1.10), naik hak ke root, lalu menembus lab-internal-01 (10.0.5.7). Belum coba? Kerjakan dulu di Simulasi Penuh Offensive.

Etika sebelum eksploitasi

Materi ini untuk lab milik sendiri. Selalu baca ROA/izin tertulis sebelum menguji sistem mana pun — termasuk saat latihan di sandbox.

#LangkahPerintahOutput kunci / tujuan
1Peta target + izincat lab/targets.txt && cat lab/roa.txtKonfirmasi scope & rules of engagement.
2Scan port & layanannmap -sV 192.168.1.10Ditemukan 22/ssh & 80/http. Port 22 jadi gerbang masuk.
3Masuk lewat port terdeteksissh webadmin@lab-web-01Foothold — shell interaktif sebagai webadmin.
4Enumerasi hak istimewasudo -l(root) NOPASSWD: /opt/backup.sh — celah eskalasi.
5Eksploitasi sudoid && sudo /opt/backup.sh && whoamiroot — privilege escalation sukses.
6Petakan segmen internalip route && nmap -sV 10.0.5.7Segmen 10.0.5.0/24; 21/ftp terbuka di internal.
7Serang layanan internalhydra -l guest -P /opt/lab/wordlists/passwords.txt ftp://10.0.5.7Kredensial FTP lemah guest:secret123.
8Bukti & rekapcat /root/root.txt; scoreFlag root + seluruh misi tercatat di scoreboard.

Pelajari di tiap langkah

Inti 1-3 Recon & Entry

Scan bisa mahal dan berisik — -sn dulu untuk host discovery, -sV untuk versi layanan. Port yang terbuka bukan kelemahan; layanan di baliknya yang menjadi vektor. Di sini port 22 langsung dipakai — itulah mengapa penyerang tidak perlu temuan rumit bila SSH dengan kredensial lemah tersedia.

Inti 4-5 Privilege Escalation

Pola klasik: user biasa punya akses ke script yang berjalan sebagai root. Selalu periksa sudo -l, SUID, cron, dan capability. Buktikan dampak seminimal mungkin — satu eksekusi untuk konfirmasi cukup.

Inti 6-7 Lateral Movement

Web server menjadi batu loncatan ke segmen yang tidak terlihat dari luar. ip route menyingkap segmen internal, lalu layanan lama (vsftpd) dengan kredensial lemah ditembus. Satu titik masuk bisa menjalar ke seluruh segmen.

Inti 8 Bukti & Laporan

Flag dan scoreboard memberi bukti objektif. Dalam pentest nyata, setiap langkah punya artefak: screenshot, perintah yang dijalankan, timestamp, dan hash bukti — itulah bahan laporan yang tahan audit.

02 — write-up blue team

Lab Pertahanan: Alert → Validasi → Blokir

Misi: ambil alert, buktikan insiden dari artefak, kunci bukti, blokir sumber serangan, dan verifikasi. Belum coba? Kerjakan dulu di Simulasi Penuh Defensive.

#LangkahPerintahOutput kunci / tujuan
1Baca alert pertamacat /var/log/suricata/fast.logKoneksi keluar ke 45.155.205.11:4444 — pola C2.
2Validasi serangan brutegrep 'Failed password' /var/log/auth.log | awk '{print $11}' | sort | uniq -cRatusan percobaan gagal dari satu IP (45.155.205.11).
3Konfirmasi keberhasilangrep 'Accepted password' /var/log/auth.logSatu login berhasil untuk webadmin dari IP sama → insiden.
4Korelasi lintas sumbergrep sqlmap /var/log/access.logPola injeksi SQL (UA sqlmap/1.7) — scope makin luas.
5Catat IOC & kunci bukticat lab/ioc-list.txt && sha256sum /var/log/auth.logBukti di-hash sebelum kontainmen, supaya jejak tak hilang.
6Blokir sumber seranganufw deny from 45.155.205.11 && iptables -A INPUT -s 45.155.205.11 -j DROPKontainmen dua lapis: host (ufw) + edge (iptables).
7Verifikasi aturanufw status verbose && iptables -L -nIP tercekam DENY di kedua firewall.
8Rekap & tindak lanjutflag FLAG{blue-team} && scoreMisi tercatat; lanjut ke eradication & lessons learned.

$ ufw deny from 45.155.205.11 && iptables -A INPUT -s 45.155.205.11 -j DROP
$ ufw status verbose && iptables -L -n
$ flag FLAG{blue-team} && score

Prinsip di balik solusi

Kontainmen tanpa menghancurkan bukti

Urutannya disengaja: bukti dikunci dulu (hash), baru sumber diblokir. Hal yang sama berlaku di dunia nyata — reboot/format menghancurkan memory dan proses yang paling berharga untuk forensik. Setelah kontainmen, lanjutkan ke eradication (hapus persistence, rotasi kredensial) dan recovery terverifikasi, seperti pada Data Collection sampai Mengamankan.
